# RELEASE_NOTES.md

> Репозиторий проекта: https://github.com/TR-Artem/medical_booking

## Релиз 0.4.0 — 25.11.2026

### Что изменилось

- Вход по e-mail, сброс и смена пароля.
- Письма отправляются асинхронно через Celery, для демо добавлен Mailpit.
- Напоминания за 24 часа включены миграцией, без ручной настройки Beat.
- Rate limit входа, отдельный сисадмин для Django admin, health-check и бэкапы.
- Конфликты кабинетов, поиск и пагинация, статус «Подтверждено», страницы 404/500.
- E2E-тесты Playwright и smoke-сборка Docker в CI.

### Как проверить

1. `make deploy && make seed`
2. http://localhost — войти `patient@test.ru / Test1234!`, записаться, отменить и записаться снова.
3. Письма — http://localhost:8025.
4. `make health` → `status: ok`.
5. `make check` → ruff, black и 75 тестов.

## Релиз 0.2.0 — 08.11.2026

### Что изменилось

Закрытые разделы теперь честно сообщают об отказе: вместо переадресации на главную пользователь видит страницу «Доступ запрещён» (HTTP 403) с объяснением и кнопками возврата. Это касается панели администратора, управления пользователями и кабинета врача.

Дополнительно проект подготовлен к сопровождению: добавлен CI, релизные скрипты и документы поддержки.

### Что исправлено

- Инцидент BUG-12: пациент или врач при попытке открыть чужой раздел не понимал, почему его вернуло на главную. Теперь причина видна, а в логах и тестах фиксируется код 403.
- Тесты прав доступа: 7 новых проверок (всего 44).

### Как проверить

1. Запустить стенд: `make deploy`.
2. Войти пациентом (`patient` / `Demo1234!`).
3. Открыть http://localhost/appointments/admin/dashboard/ — должна открыться страница «Доступ запрещён» с кодом 403.
4. Войти сисадмином (`sysadmin` / `Demo1234!`) — панель открывается.
5. Запустить `make check`: ruff, black и 44 теста проходят.

### Что вошло в релиз

- `templates/403.html`, `access_denied` в `apps/appointments/views.py`;
- `apps/appointments/tests/test_access.py`;
- `.github/workflows/ci.yml`;
- скрипты `build.bat`, `release-check.bat`, `create-release.bat`;
- `CHANGELOG.md`, `INCIDENT_REPORT.md`, `RELEASE_CHECKLIST.md`.

Релизный архив: `release/medical_booking_20261108.zip`.

### Ограничения

- Демо-стенд работает по HTTP, без TLS.
- Нет ограничения попыток входа и мониторинга.
- Демо-учётные записи создаются командой `create_demo_data` и предназначены только для локальной проверки.
