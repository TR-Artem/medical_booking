# SECURITY.md

> Репозиторий проекта: https://github.com/TR-Artem/medical_booking

Документ описывает базовые меры безопасности проекта «Онлайн-запись в медицинский центр».

## Секреты

- Настоящие значения хранятся только в `.env` и `.env.production`, оба файла в `.gitignore`.
- В репозитории есть только шаблоны: `.env.example` и `.env.production.example` с заглушками `change_me`.
- При компрометации: заменить `SECRET_KEY` и пароли БД, перезапустить сервисы, отозвать ключи.

## Версии зависимостей

- Runtime-зависимости закреплены в `requirements.txt`, инструменты разработки — в `requirements-dev.txt`.
- Проверка уязвимостей: `make deps-check` (pip-audit). На 08.11.2026 уязвимостей не найдено.

## Доступ и роли

Роли: пациент, врач, администратор клиники, системный администратор.

- Панели администратора доступны только ролям `admin` и `sysadmin`.
- Пациент не может открыть чужую запись: отмена чужой записи возвращает 404.
- Закрытые разделы без входа перенаправляют на страницу входа.

## Конфигурация

- `DEBUG=False` в production; трассировки не отдаются.
- `ALLOWED_HOSTS=localhost,127.0.0.1`, CORS ограничен явным списком origin.
- Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`.
- Cookies: `HttpOnly` для сессии и CSRF.
- Контейнеры приложения работают от пользователя `app` (uid 100), не от root.

## Данные

- Резервная копия: `make backup` (`pg_dump` в `backups/`).
- Восстановление: `make restore BACKUP=backups/<файл>.sql` в отдельную БД.
- Каталог `backups/` и файлы `*.sql`, `*.dump` исключены из git.

## Ограничения демо-стенда

- HTTPS не настроен: `SECURE_SSL_REDIRECT=False`, `SECURE_HSTS_SECONDS=0`. Включается переменными окружения после установки сертификата.
- Нет ограничения попыток входа и мониторинга.
