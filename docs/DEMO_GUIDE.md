# DEMO_GUIDE.md

> Репозиторий проекта: https://github.com/TR-Artem/medical_booking

## Подготовка стенда

```bash
make deploy     # production локально, http://localhost
make seed       # пользователи, врачи, расписание, записи
```

Для dev-стенда: `make run` и `make seed-dev`, адрес http://localhost:8080.
Письма: http://localhost:8025 (Mailpit).

## Демо-доступы

| Роль | Логин | Пароль |
|---|---|---|
| Администратор клиники | `admin@test.ru` | `Test1234!` |
| Системный администратор | `sysadmin@test.ru` | `Test1234!` |
| Врач-кардиолог | `doctor@test.ru` | `Test1234!` |
| Врачи других специальностей | `doctor2@test.ru` … `doctor5@test.ru` | `Test1234!` |
| Пациент | `patient@test.ru` | `Test1234!` |

Логин совпадает с e-mail, вводится целиком. Вход работает и по username, и по e-mail.
Сброс пароля — ссылка «Забыли пароль?» на странице входа.

## Сценарий показа (7–10 минут)

1. **Главная** — http://localhost/. Специальности, врачи, кнопки записи.
2. **Врачи** — /appointments/doctors/. Фильтр, поиск, 5 врачей.
3. **Запись** — войти пациентом `patient@test.ru`, открыть карточку врача, выбрать слот.
   - Свободные слоты видны на 7 дней; прошедшее сегодня время скрыто.
   - Обеденный перерыв и занятые слоты недоступны.
   - После бронирования запись появляется в «Мои записи», письмо — в Mailpit.
4. **Мои записи** — /appointments/my/. Показать 3 демо-записи.
   - Отменить запись → слот снова доступен → записаться на него повторно.
5. **Кабинет врача** — выйти и войти `doctor@test.ru`.
   - Запись на сегодня, жалоба пациента, кнопки «Подтвердить» / «Явился» / «Неявка».
6. **Админ-панель** — войти `admin@test.ru`.
   - Статистика: записи сегодня, 5 врачей, 6 кабинетов.
   - Расписание: 35 записей на 7 дней, слоты и кабинеты; конфликт кабинета не создаётся.
   - Кабинеты: 6 кабинетов, деактивация.
7. **Сисадмин** — войти `sysadmin@test.ru`.
   - Управление пользователями: /appointments/admin/users/.
   - Django admin: /django-admin/ (полный доступ только у сисадмина).
8. **Health-check** — /healthz/ отдаёт JSON `{"status": "ok", "db": true, "version": "0.4.0"}`.

## Что считается успешной проверкой

- Все страницы открываются без 500.
- Вход работает под всеми пятью ролями, по логину и по e-mail.
- На главной и в списке врачей — 5 врачей без дублей; поиск и фильтр работают.
- Слоты есть на каждый из 7 дней; занятые, обеденные и прошедшие не показываются.
- Запись создаётся, отображается у пациента и врача, отменяется и создаётся повторно.
- Письма подтверждения и отмены видны в Mailpit.
- `make check` — ruff, black и 75 тестов проходят.
- `make check-deploy` — сервисы `running`, HTTP 200, в логах нет traceback.
- `make health` — `status: ok`.

## Известные ограничения

- Демо-письма складываются в Mailpit; реальная отправка требует SMTP-провайдера.
- Одна клиника, без филиалов и мультитенантности.
- Демо-пароль публичный — только для стенда.
- VPS-развёртывание требует домена и доступов; локальный стенд работает по HTTP.
