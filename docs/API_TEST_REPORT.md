# API_TEST_REPORT.md

## Что проверялось

Проект реализован как серверное Django-приложение с HTML-шаблонами. Публичного REST API нет: в `medical_booking/urls.py` подключены только `django-admin`, `apps.core`, `apps.accounts`, `apps.appointments`. DRF установлен в зависимости, но эндпоинты не описаны.

Поэтому вместо Swagger/Postman проверялись HTTP-маршруты приложения: коды ответов, редиректы и время отклика.

## Результаты проверки маршрутов

| Маршрут | Код | Время | Комментарий |
|---|---|---|---|
| `/` | 200 | 0,018 с | главная страница |
| `/accounts/login/` | 200 | 0,002 с | форма входа |
| `/accounts/register/` | 200 | 0,002 с | форма регистрации |

## Ошибочные сценарии

- Запрос защищённого раздела без авторизации: 302 на `/accounts/login/?next=...` — ожидаемо.
- Запрос админ-раздела пациентом: 302 на главную с сообщением «Доступ только для администраторов клиники». Рекомендуется отдавать 403 (BUG-12).
- Несуществующий адрес: 404, трассировка не раскрывается (`DEBUG=False`).

## Производительность

- Среднее время ответа главной страницы: 0,007 с на 10 последовательных запросах.
- Все страницы отвечают быстрее 20 мс на локальном стенде.

## Вывод

HTTP-слой работает корректно: успешные и ошибочные сценарии обрабатываются, права доступа разграничены, коды ответов осмысленные. REST API в проекте отсутствует, поэтому проверки Postman/Swagger не применимы; при добавлении API потребуется отдельный контракт и тесты.
