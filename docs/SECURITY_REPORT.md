# Отчёт по безопасности (этап 5, УП.03)

Студент: Гаврик Артём Олегович, группа 9-3-РПО-23-1
Проект: «Онлайн-запись пациентов в медицинский центр»
Репозиторий: https://github.com/TR-Artem/medical_booking, ветка `feature/up03-stage5-security`

## 1. Что проверялось

Секреты в репозитории, зависимости на уязвимости, роли и доступ к чужим данным, CORS и `DEBUG`, заголовки безопасности, запуск контейнеров от непривилегированного пользователя, резервное копирование и восстановление, открытые порты, логи.

## 2. Инструменты

`git grep`, `git ls-files`, pip-audit, Django test client, `pg_dump`/`psql`, `docker compose ps`, `nc`, `docker logs`.

## 3. Что найдено

1. Устаревшие зависимости: Django 5.0.4 (16 известных уязвимостей), Pillow 10.3.0, DRF 3.15.1, simplejwt 5.3.1 — это главная проблема на входе.
2. Контейнеры приложения работали от root (предупреждение Celery).
3. В `requirements.txt` лежали инструменты разработки (ruff, black), увеличивая поверхность атаки в production-образе.

Критических проблем с секретами не найдено: `.env` в git отсутствует, в репозитории только шаблоны с `change_me`.

## 4. Что исправлено

- Django обновлён до 5.2.19, DRF до 3.18.3, simplejwt до 5.5.1, Pillow до 13.0.0, django-celery-beat до 2.9.0. Повторный pip-audit: «No known vulnerabilities found».
- Инструменты разработки вынесены в `requirements-dev.txt`.
- В Dockerfile создан пользователь `app`, контейнеры запускаются с `uid=100`, не от root.
- Добавлены заголовки безопасности: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `HttpOnly` cookies.
- `.gitignore` дополнен каталогом `backups/` и файлами `*.sql`, `*.dump`.
- Добавлен `SECURITY.md` с правилами работы с секретами и данными.

## 6. Какие риски остались

- Нет HTTPS: трафик не шифруется, `SECURE_SSL_REDIRECT=False` (R-04).
- Нет ограничения попыток входа (R-05).
- Нет регулярного автоматического резервного копирования (R-06, частично).
- Нет мониторинга и централизованных логов (R-10).

Меры и сроки — в `RECOMMENDATIONS.md` и `RISK_REGISTER.md`.

## 7. Вывод

Базовая проверка безопасности пройдена: секреты не утекают, зависимости без известных уязвимостей, доступ по ролям и к чужим данным закрыт, контейнеры не работают от root, резервное копирование и восстановление проверены. Для промышленной эксплуатации остаётся настроить HTTPS, ограничение попыток входа, регулярные backup и мониторинг.
