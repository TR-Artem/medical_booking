# RISK_REGISTER.md (этап 5)

> Репозиторий проекта: https://github.com/TR-Artem/medical_booking

Реестр рисков безопасности и эксплуатации. 10 рисков: 5 по безопасности, 5 по эксплуатации.

| ID | Риск | Причина / признак | Вероятность | Влияние | Мера снижения | Статус |
|---|---|---|---|---|---|---|
| R-01 | Утечка секретов | `.env.production` с паролями и `SECRET_KEY` | Средняя | Высокое | `.gitignore`, шаблоны без секретов, поиск секретов, ротация ключей | Мера внедрена |
| R-02 | Доступ к чужим данным | Нет проверки владельца ресурса | Низкая | Высокое | Проверка `patient=request.user`, тест: чужая запись → 404 | Мера внедрена |
| R-03 | Уязвимая зависимость | Устаревшие Django и Pillow | Средняя | Высокое | Обновление версий, `pip-audit` в проверках | Мера внедрена |
| R-04 | Перехват трафика | HTTP без TLS | Средняя | Высокое | HTTPS/reverse-proxy, `SECURE_SSL_REDIRECT`, HSTS | Открыт |
| R-05 | Подбор пароля | Нет ограничения попыток входа | Средняя | Среднее | Rate limiting, блокировка после N попыток | Открыт |
| R-06 | Потеря данных | Нет регулярного резервного копирования | Средняя | Высокое | `make backup`, восстановление проверено, план: cron/CI | Частично |
| R-07 | Отказ после перезапуска | Порядок запуска, кеш IP у nginx | Средняя | Среднее | `restart: unless-stopped`, healthcheck, `restart nginx` в деплое | Мера внедрена |
| R-08 | Открытый лишний порт | Неверная публикация портов | Низкая | Среднее | Наружу только 80, проверка `make ports-check` | Мера внедрена |
| R-09 | Работа от root | Контейнер по умолчанию root | Средняя | Высокое | Пользователь `app` в Dockerfile | Мера внедрена |
| R-10 | Нет мониторинга | Логи только локально | Высокая | Среднее | Централизованные логи, алерты, healthcheck | Открыт |

## Связь с проверками

- R-01: `make security-check`, скриншоты 01–03.
- R-03: `make deps-check`, после обновления — «No known vulnerabilities found».
- R-09: `id` внутри контейнера — `uid=100(app)`.
- R-06: backup и restore выполнены, отчёт `BACKUP_RESTORE_REPORT.md`.
